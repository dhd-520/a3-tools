## 状态

## 目标
陛下场景：「查账套 8088 单号 YD-260817-0284 的支付方式、支付时间」→ AI 自己探索表结构 → 自己拼 SQL → 自动查询

## 陛下要求
- AI **灵活运用**，不要写死 Skill 步骤
- 不同问题查不同表（问题 A 查 A+B，问题 B 查 A+C），AI 自主决定 JOIN
- 账套走现有连接模式（直连走直连，代理走代理，不改配置）

## 新增 3 个 Action

| Action | 权限 | 功能 |
|--------|------|------|
| `list_tables` | 读本地 | 列出账套下所有用户表（AI 探索用） |
| `get_table_schema` | 读本地 | 查指定表的列结构（列名 + 类型） |
| `execute_sql` | 网络（高危） | 执行 SELECT 查询（拒绝写操作） |

## 连接模式复用

完全复用 `A3Tools.Common.DataAccess.DataAccessFactory.Create(account)`：
- `account.ConnectionMode == Direct` → `DirectDataAccess`
- `account.ConnectionMode == Http` → `HttpDataAccess`

不新加任何配置字段，跟陛下手动点 SQL 查询工具走完全一样的路径。

## SQL 安全策略（execute_sql）

| 检查 | 规则 |
|------|------|
| **关键字白名单** | 只允许 SELECT / WITH / SHOW / DESCRIBE / DESC / EXPLAIN 开头 |
| **关键字黑名单** | INSERT / UPDATE / DELETE / DROP / CREATE / ALTER / TRUNCATE / EXEC / EXECUTE / MERGE / GRANT / REVOKE / BACKUP / RESTORE / SHUTDOWN / KILL |
| **多语句拦截** | 拒绝分号后还有内容 |
| **行数限制** | 自动加 `TOP N`（默认 1000，最大 5000），已有 TOP/OFFSET 则不重复 |
| **高危确认** | 弹窗 + 输入 `EXECUTE` 确认（ConfirmActionForm） |

## AI 引导（System Prompt）

新增「业务查询工作流」段落：
1. list_tables 探索
2. get_table_schema 确认列名
3. execute_sql 查询
4. 自然语言组织结果

「灵活性原则」段落强调：不要假设表名、JOIN 大胆用、模糊匹配用 LIKE、时间范围用 BETWEEN。

## 已知限制
- AI 拼 SQL 可能偶尔出错（幻觉），陛下要在弹窗里 review
- SQL Server 语法（TOP N），不是 MySQL 的 LIMIT
- 暂不支持事务、暂不支持跨账套 JOIN（单次 execute_sql 只能查一个账套）
- 列名 AI 可能猜错 → 会查 get_table_schema 二次确认
